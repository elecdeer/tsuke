# 店舗の管理画面

設定の下の `/settings/places` で、登録されている店舗を整理する。店舗は数百件あるので、名前・別名の検索と並び替えで探す。

## できること

- **名前の変更。** 取引は店舗を ID で参照するので書き換えない。他の店舗と同じ名前にはできず、統合を案内する
- **統合。** 取引を統合先へ付け替えて統合元を消す。統合元の名前と別名は統合先の別名に残し、ヒントとチェーンは統合先になければ引き継ぐ。OpenPOI の施設の情報は後から引き直せないので、統合先に施設の情報がなければ出典と一緒にまとめて移す（項目ごとに混ぜない）
- **未使用の店舗の削除。** 取引が 1 件もない店舗だけを消せる
- **AI の読み取り用の別名とヒントの設定。** レシートや明細での書かれ方と、店の補足を店舗に持たせる

## 決めたこと

- **統合元はアーカイブせず消す。** フェーズ1では統合元をアーカイブすると決めていたが、登録は店舗を名前で探すので、名前が残っていると同じ表記の登録が隠れた統合元に付いてしまう。統合した後は参照がないので消せる
- **アーカイブ済みの店舗の名前を登録で入力すると元に戻す。** また使い始めた店舗なので候補に戻す。取引の編集では、店舗を変えたときだけ戻す。過去の取引を直しただけでは戻さない
- **アーカイブの操作はこの画面に置かない。** アーカイブ済みの店舗も一覧には出すので、名前の変更・統合はできる。アーカイブ済みの店舗へ統合すると元に戻す
- **別名は AI の読み取りにだけ使う。** 手入力の候補や登録時の名前の照合には使わない
- **別名は `places.aliases` に JSON の配列で持つ。** 別名で SQL から引くことがなく、店舗と一緒に読み書きするだけなので、別のテーブルにしない

## AI の読み取りへの渡し方

- 店舗の行に `aka:` と `hint:` を添える（`Amazon [3x, 2026-10-01]; aka: AMAZON.CO.JP / ｱﾏｿﾞﾝ; hint: ...`）
- 別名やヒントのある店舗は、最近使った店舗の上限（ページ・レシートは 20 件、明細は 200 件）から外れていても、未使用でも候補に入れる。設定した手がかりが上限で切られて効かなくならないようにするため
- AI が別名をそのまま返したら、店舗の正式な名前に直す。そのまま登録すると、同じ表記の新しい店舗が作られるため。全角・半角と大文字・小文字の違いは無視して比べる
- 明細では、AI が店舗を選べなかった行でも、明細の表記が店舗名か別名に一致すれば店舗を決める
- 拡張機能が読む `GET /api/places` の形は変えない
