# 立替の要件

割り勘、会社の経費、家族の分の買い物のように、他の人の分まで払った取引がある。今は取引全体を集計に含めるか含めないかしか選べず、一部だけ他の人の分という支出を正しく集計できない。

取引の一部を立替として記録し、自分が負担した分だけを支出として集計できるようにする。記録済みの収入を支出に紐付けると立替額が確定し、まだ返ってきていない立替を未入金として確かめられる。

## 前提になる状況

- **品目が立替分で綺麗に分かれるとは限らない。** 割り勘では 1 つの品目の一部だけが立替になる。レシートに値引きの品目が混ざることもある
- **入金先は支払元と同じ口座とは限らない。** カードで払い、銀行口座に返ってくることがある
- **立替と入金は 1 対 1 とは限らない。** 複数の立替がまとめて返ってくることも、割り勘の相手が別々に送金して 1 件の立替に複数の入金が入ることもある。額がずれることも、返ってこないこともある
- **収入は一括で追加されることがある。** CSV の読み取りなどで入るので、記録の時点では立替の入金かどうかが分からない

## できること

### 立替額の入力

- 取引の編集画面で、支出の取引に立替額を入れられる。新規登録の画面と拡張機能には入れない
- 紐付けの前の立替額は仮の額として扱う。額は手で入れるか、品目を元に入れる
- 品目に立替の対象の印を付けられる。印を変えると対象の品目の合計が額に入り、その額は手で直せる
- 印がなければ全品目が対象になる。割り勘では印を付けずに額だけを入れる

### 入力できる範囲

- 立替額は、紐付けた額の合計（紐付けがなければ 0）以上で、対象の品目の合計を超えない
- 品目の金額や印を変えて立替額が範囲外になったら、保存時に誤りとして知らせる。額を自動で直さない

### 立替の状態

状態は持たず、立替額と紐付けた額の合計を比べて決める。

| 状態     | 条件                                 | 未入金の残り              |
| -------- | ------------------------------------ | ------------------------- |
| 仮       | 立替額が 0 より大きく、紐付けがない  | 立替額                    |
| 一部入金 | 紐付けがあり、合計が立替額より少ない | 立替額 − 紐付けた額の合計 |
| 確定     | 紐付けがあり、合計が立替額と一致する | なし                      |

### 集計

- 月の支出の合計、カテゴリ別、内訳別の集計は、品目の金額から立替の按分額を引いた額で計算する。仮と一部入金の立替額も同じように引く
- 按分額は、立替額を対象の品目の金額に比例して分けた額にする。端数は按分額の和が立替額と一致するように調整する
- 負担額が 0 になったカテゴリと内訳は、集計に出さない
- 集計の設定はこれまでどおり効く。「集計に含めない」取引は、立替額に関係なく集計に入らない

### 収入との紐付け

- 立替分の入金は、今の収入の取引のまま記録する。手入力でも一括の追加でもよく、新しい種類は作らない
- 紐付けは、記録済みの収入の詳細画面から作る。支出の詳細画面には、紐付いた収入へのリンクと未入金の残りだけを出す
- 支出と収入は多対多で紐付けられる。紐付けごとに、収入からその支出へ充てる額を持つ
- 候補には、未入金の残りがある支出を新しい順に先に出す。確定済みの支出や立替額のない支出も、合わせて 200 件まで探して選べる。それより古い支出は、仮の立替額を入れると未入金として候補に出る
- 紐付けると、収入を「集計に含めない」に変える。立替分が収入にも数えられ、二重に計上されるのを防ぐ
- 集計に含める状態で追加された収入は、紐付けるまで収入の集計に入る。その間は、仮の額を引いた支出と合わせて収支が多めに出る

### 収入の配分

- 収入を支出 1 件に紐付けるなら、収入の金額をそのまま充てる
- 複数の支出に紐付けるなら、未入金の残りに比例して分けた額を候補に出し、保存前に支出ごとに直せる。全支出の残りが 0 なら、対象の品目の合計から紐付け済みの額を引いた額に比例させる
- 収入の金額はすべて立替に充てる。充てる額の和は収入の金額と一致させる
- 支出ごとの紐付けた額の合計は、対象の品目の合計を超えない
- 収まらないときは紐付けられない。立替分とそれ以外を 2 件の収入に分けるよう案内する（給与と一緒に振り込まれた経費、多めにもらった分など）

### 紐付けによる確定

- 紐付けると、立替額を紐付けた額の合計で上書きして確定する。これが既定の動きになる
- 紐付けのときに支出ごとに「まだ入金がある」を選べる。選ぶと立替額を変えず、残りは未入金に残る。合計が立替額を超えるときは、立替額を合計まで上げる
- 残りが返ってこないと分かったら、立替額を紐付けた額の合計まで下げて確定する。編集画面にこのための操作を用意する
- 確定しても対象の品目の印はそのまま残す。額だけを置き換えるので、品目へ分け直す操作は要らない

### 紐付けの後の変更

| 操作                     | 扱い                                                                                                           |
| ------------------------ | -------------------------------------------------------------------------------------------------------------- |
| 支出の立替額を手で変える | 紐付けた額の合計以上の範囲でできる。合計より上げると、差額が未入金の残りになる                                 |
| 収入の金額を変える       | 支出 1 件なら充てる額を変える。複数なら配分を確認する。確定していた支出の立替額は新しい合計で上書きする        |
| 品目の金額や印を変える   | できる。立替額が範囲外になるなら保存時に誤りにする                                                             |
| 紐付けを外す             | 支出の立替額は変えず、外した額が未入金の残りに戻る。残りの支出がある収入は配分を確認する。集計の設定は変えない |
| 収入を削除する           | 紐付けが消える。支出の立替額は変えず、その額が未入金の残りに戻る                                               |
| 紐付いた支出を削除する   | できない。先に紐付けを外す                                                                                     |

### 一覧と絞り込み

- 取引一覧の金額は取引の全額のまま出し、立替がある取引には「うち立替」の額と、状態を添える。一部入金なら残りも添える
- 一覧の上の支出の合計も全額のままにし、立替があれば「うち立替」の合計を添える
- 取引一覧を「立替あり」で絞り込める。他の絞り込みと組み合わせられる
- 取引一覧を「未入金」で絞り込める。未入金の残りがある支出を、月をまたいで全期間から出す
- 全く返ってこないと分かった立替は、仮の額を 0 にして未入金から外す

## 例

### 割り勘

カードで払った 3 人の飲み会で、2 人分を立て替えた場合。印は付けず、額に 2,400 を入れる。

| 品目     | 金額  | 按分額 | 負担額 |
| -------- | ----- | ------ | ------ |
| 食事     | 3,000 | 2,000  | 1,000  |
| 飲み物   | 1,000 | 667    | 333    |
| クーポン | −400  | −267   | −133   |
| 合計     | 3,600 | 2,400  | 1,200  |

- カードの残高は 3,600 減り、明細の金額とも一致する
- 月の支出には 1,200 だけ入り、取引は未入金として絞り込みに出る
- 銀行口座の 2,000 の収入を CSV から追加すると、この時点では収入の集計に入る
- その収入の詳細画面から支出を紐付けると、立替額が 2,000 に確定する。月の支出は 1,600 になり、取引は未入金から外れる。収入は集計に入らなくなり、銀行口座の残高は 2,000 増えたままになる

### 割り勘の相手が別々に送金した場合

同じ飲み会で、立替額 2,400 に対して 2 人から別々に入金があった場合。

| 操作                                      | 立替額 | 紐付けた額の合計 | 未入金の残り | 月の支出 |
| ----------------------------------------- | ------ | ---------------- | ------------ | -------- |
| A の 1,200 を「まだ入金がある」で紐付ける | 2,400  | 1,200            | 1,200        | 1,200    |
| B の 1,000 をそのまま紐付ける             | 2,200  | 2,200            | なし         | 1,400    |

B から入金がなければ、取引は未入金に残り続ける。返ってこないと分かった時点で立替額を 1,200 に下げて確定すると、月の支出は 2,400 になる。

### 品目で分かれる立替

自分の食品 1,000 と友人の日用品 2,000 が同じレシートにあり、日用品に印を付けた場合。額には 2,000 が入り、集計では食品 1,000、日用品 0 になる。友人から 1,500 だけ返ってきて紐付けると、食品 1,000、日用品 500 になる。

## 決めたこと

- **取引の全額は変えず、立替額を別に持つ。** 口座の残高は品目の金額の和で計算し、明細との突合も全額で照合する。全額を減らすとどちらも合わなくなる
- **立替額は取引に 1 つだけ持ち、品目には対象の印だけを持つ。** 品目ごとに額を持つと、確定のたびに品目へ分け直す処理と画面が要る。印と比例の按分にすれば、確定は額を置き換えるだけで済む。「この品目は全額、あの品目は半額」のような指定はできず、そのカテゴリ別の額は近似になる
- **印は入力の補助だけにしない。** 選択を保存しないと集計は全品目からの比例になり、品目で分かれる立替の例が食品 333、日用品 667 のように実態とずれる
- **立替用の負の品目は使わない。** 値引きと同じ形で表せそうに見えるが、品目の和が減るので残高と突合が合わなくなる
- **紐付けは別のテーブルにし、充てる額を持つ。** まとめて入金と別々の入金の両方があるので多対多になり、1 件の収入のどれだけがどの支出の分かは取引の列では表せない
- **実際に入った額を正とし、差額は持たない。** 紐付けで立替額を上書きするので、見込みとのずれを別に記録したり手で直したりしなくて済む
- **まだ入金がある場合だけ、紐付けのときに選ぶ。** 紐付けのたびに上書きすると、1 人目の入金で立替額が下がり、2 人目の分を未入金で追えなくなる。多くの場合は 1 回で確定するので、既定は今のルールのままにする
- **確定かどうかの状態を列に持たない。** 立替額と紐付けた額の合計を比べれば決まる。別に持つと 2 つがずれたときの扱いが要る
- **未入金の絞り込みだけ月をまたぐ。** 取引一覧は 1 か月単位だが、前の月の立替ほど見落としやすい
- **立替分の入金を収入と分けない。** 収入は一括で追加されるので、記録の時点では区別できない。記録済みの収入に後から紐付ければ足りる
- **紐付けは収入の詳細画面からだけ作る。** 記録された収入を見て、どの立替の入金かを判断する流れに合う。複数の支出を選ぶ操作も 1 画面で済む
- **立替額の入力は編集画面だけにする。** 精算額が決まるのは登録の後のことが多い。登録画面への追加は、使ってみて必要になってから考える

## やらないこと

- 立替の相手の管理
- 品目ごとの立替額の保存
- 未入金額の全期間の合計の表示、返ってきていない立替の通知
- 立替の入金専用の種類や入力画面
- 支出の詳細画面や収入の登録時に紐付けを作ること
- 新規登録の画面、拡張機能、AI の読み取りでの立替の入力
- 収入・振替・残高調整の取引での立替

## 既存の動きへの影響

| 対象                                            | 扱い                                                                                 |
| ----------------------------------------------- | ------------------------------------------------------------------------------------ |
| スキーマ（`db/schema.ts`）                      | 取引に立替額、品目に対象の印を足す。支出と収入と充てる額を持つ紐付けのテーブルを足す |
| 月の集計（`src/ledger/summary.ts`）             | 取引ごとの按分額を引く。端数の調整があるので SQL だけでは出さない                    |
| 取引の編集（`src/ledger/transactionEdit.ts`）   | 立替額と印を読み書きし、紐付けと配分、確定、範囲の検証を足す                         |
| 取引の削除（`src/ledger/transactionEdit.ts`）   | 紐付いた支出の削除を止める。収入の削除では紐付けを消す                               |
| 取引一覧（`src/ledger/transactions.ts` と画面） | うち立替の表示と絞り込みを足す。未入金は月の条件を外す                               |
| 口座の残高（`src/ledger/balances.ts`）          | 変えない。全額で計算する                                                             |
| 明細との突合（`src/ledger/statements.ts`）      | 変えない。全額で照合する                                                             |
| Zaim CSV の取り込み（`src/import/zaimCsv.ts`）  | 変えない。立替額は 0、印なし、紐付けなしで入る                                       |

Zaim CSV の取り込みは総入れ替えなので、取り込んだ取引に付けた立替額と印、紐付けは再取り込みで消える。再取り込みを止めないよう、紐付けのテーブルの外部キーは取引の削除に連動して消えるようにし、紐付いた支出の削除を止めるのはアプリ側で行う。手入力の取引は残り、取り込んだ収入に紐付いていた手入力の支出は、消えた額が未入金の残りに戻る。手入力の収入に複数の支出を紐付けていて一部が消えると、和が収入の金額と合わなくなるので、紐付けを直す。

## 完了の条件

- 割り勘の例を編集画面で作ると月の支出に 1,200 だけ入り、2,000 の収入を紐付けると 1,600 になる
- 別々に送金した例の操作をすると、各段階の立替額、未入金の残り、月の支出が例のとおりになる
- 品目で分かれる立替の例で、カテゴリ別の集計が例のとおりになる
- 立替額を付けても紐付けても、支出の支払元の残高と明細との突合の結果が変わらない
- 記録済みの収入の詳細画面から紐付けを作れ、支出の詳細画面からは紐付いた収入へ移動できる
- 集計に含める状態で追加された収入を紐付けると、「集計に含めない」に変わる
- 1 件の収入を複数の支出に紐付けると候補の配分が出て、和が収入の金額と一致しないと保存できない
- 紐付けた額の合計が対象の品目の合計を超える紐付けはできず、収入を分ける案内が出る
- 紐付けた額の合計より低い立替額は保存できない
- 紐付けを外すか収入を削除すると、支出の立替額はそのままで、その額が未入金の残りに戻る
- 紐付いた支出は削除できない
- 「未入金」で絞り込むと、月をまたいで未入金の残りがある立替だけが一覧に出る
